# HSC 人机协同开发框架使用指南

Human-Synergy Collaboration

本文是 HSC（Human-Synergy Collaboration）人机协同开发框架的唯一入口。

本框架名称为 **Human-Synergy-Collaboration（HSC）**；目录以 `Human-Synergy-Collaboration` 命名（若带前缀 `2-` 仅表示同级排序，不属于名称）。对外统一简称 HSC。

一句话原则：

```text
人负责目标、边界和裁决；AI 负责整理、分析、执行和检查；需求工作台负责主流程，Superpowers 负责执行纪律，确认冻结和门禁负责防返工。
```

## 0. 执行铁律（关口必停，不得跳步）★

AI 执行任何需求时，**必须逐阶段推进，遇到确认关口必须停下等人明确回复后才继续**，严禁一次跑到底。

四个快速确认关口（详见 `01-流程层/人类快速确认指南.md`、`验收快速指南.md`）：

1. **需求澄清后** → 产出「澄清确认单」，阻塞项未拍板不得进方案/编码。
2. **编码前** → 产出「编码前理解确认」，未获"通过"不得写代码。
3. **测试后** → 产出「测试可信度报告」（AC↔测试映射/红灯证据/变异分数/假测试自检），未过不得进验收。
4. **验收** → 走「验收清单」五步，有 No-Go 不得判通过。

违规信号（出现即视为跳步，须回退）：

- 需求还含糊就写方案或代码；
- 没出「编码前理解确认」就开始改代码；
- 自写自测后直接宣称完成，未出测试可信度报告；
- 一条消息里从澄清一路做到编码/测试而中间没有停下等人确认。

> 例外：人明确说"连续执行/不用逐步确认"时可放宽；默认必停。

## 1. 先读什么

每次启动一条需求，AI 和人只需要先读这 4 个入口：

| 顺序 | 文件 | 用途 |
| --- | --- | --- |
| 1 | `README.md` | 确认 HSC 框架怎么用 |
| 2 | `02-资产层/README.md` | 确认资产层怎么用、Prompt 和 Superpowers 怎么选 |
| 3 | `02-资产层/06-Superpowers技能方法/00-技能选择总入口.md` | 确认当前阶段使用哪种执行方法 |
| 4 | 当前需求目录的 `STATUS.md` 和阶段文档 | 确认当前需求进度、已冻结事项和下一步 |

不要从多个 Superpowers 文档里自行拼规则。资产层以 `02-资产层/README.md` 为入口。需要选择执行方法时，只读 `02-资产层/06-Superpowers技能方法/00-技能选择总入口.md`。新需求默认一阶段一主文档，避免一阶段产生多个版本文档。

## 2. 目录分工

| 目录 | 定位 | 放什么 |
| --- | --- | --- |
| `00-治理层` | 边界 | AI 能不能做、谁兜底、哪些风险必须人工确认 |
| `01-流程层` | 路径 | 一条需求从输入到上线复盘怎么走 |
| `02-资产层` | 工具 | 可复用规则、模板、清单、Prompt、项目经验 |
| `03-需求工作台` | 现场 | 每条真实需求的材料、澄清、设计、代码清单、联调、验收、复盘 |
| `04-度量层` | 反馈 | 提效、返工、漏测、风险发现和体系改进记录 |

判断文件归属时只看主用途：

1. 跨需求稳定生效，放 `02-资产层`。
2. 只服务某条需求，放 `03-需求工作台/<REQ-XXX>`。
3. 定义人工边界和风险，放 `00-治理层`。
4. 定义阶段流程和准入准出，放 `01-流程层`。
5. 记录效果和改进，放 `04-度量层`。

## 3. 怎么开始一条新需求

1. 从 `03-需求工作台/REQ-模板` 复制一份新目录，命名为：

```text
REQ-XXX - 需求名称
```

2. 把所有原始材料放入：

```text
03-需求工作台/REQ-XXX - 需求名称/00-原始材料
```

3. 让 AI 按下面口令启动：

```text
启动新需求：REQ-XXX - 需求名称。

需求工作台路径：
<你的本地路径>\Human-Synergy-Collaboration\03-需求工作台\REQ-XXX - 需求名称

请按结构化流程执行：
1. 先读取根目录 README.md。
2. 再读取 02-资产层/README.md。
3. 再读取 02-资产层/06-Superpowers技能方法/00-技能选择总入口.md。
4. 再读取当前需求的 00-原始材料 和 STATUS.md。
5. 第一阶段只做需求澄清和确认冻结台账。
6. 不写代码，不进入方案设计。
7. 已确认事项写入 `01-需求澄清/需求澄清.md` 的确认冻结台账小节，后续阶段不得重复提问。
```

4. 第一阶段必须产出：

```text
01-需求澄清/需求澄清.md
```

冻结口径写入 `需求澄清.md` 的“确认冻结台账”小节，不再默认单独维护多份确认文档。

5. 之后按 00-07 阶段推进，不跳阶段。

## 4. 标准阶段和强制产物

默认执行规则：

1. 一阶段一主文档，`STATUS.md` 只做总控。
2. 不默认创建 `v1/v2/v3` 多版本文件。
3. 确认项按批次汇总，只打断用户确认当前阶段必须确认的问题。
4. 清单用于防漏，阶段文档只记录检查结论，不复制整张清单。
5. Superpowers 用于强化执行纪律，不增加额外过程文档。

| 阶段 | 目录 | 必要产物 |
| --- | --- | --- |
| 原始材料 | `00-原始材料` | 原始需求、接口文档、截图、会议记录、外部资料 |
| 需求澄清 | `01-需求澄清` | `需求澄清.md`，含确认冻结台账 |
| 影响分析 | `02-影响分析` | `影响分析.md`，含影响范围、风险点、涉及模块、涉及表和接口 |
| 方案设计 | `03-方案设计` | `方案设计.md`，含方案、关键取舍、评审结论 |
| 任务拆分 | `04-任务拆分` | `任务拆分.md`，含任务包、验收断言、任务级验证目标和 TDD 适用性 |
| 开发与联调 | `05-开发与联调` | `开发联调记录.md`，含代码理解、实施落点、任务 TDD 记录、外部接口、代码清单、联调记录 |
| 测试与验收 | `06-测试与验收` | `测试验收.md`，含测试结果、完成前验证门禁、验收结论 |
| 复盘沉淀 | `07-复盘沉淀` | `复盘沉淀.md`，含可复用经验、资产层更新建议 |

## 5. 编码前必须满足的门禁

AI 进入正式编码前，必须完成以下 4 件事：

| 门禁 | 产物 |
| --- | --- |
| 需求冻结结论 | 在 `05-开发与联调/开发联调记录.md` 引用 `01-需求澄清/需求澄清.md` 的冻结结论 |
| 项目结构理解 | 在 `开发联调记录.md` 说明模块、包、代码风格、参考类 |
| 实施落点清单 | 在 `开发联调记录.md` 明确新增/修改哪些文件、接口、表、配置、测试 |
| 任务 TDD 执行 | 在 `开发联调记录.md` 按任务记录红-绿-重构；无法 TDD 的任务记录原因和替代验证 |

缺任意一项，不写代码。

## 6. 外部接口接入门禁

涉及三方接口时，不能只读接口文档的一部分。默认在 `05-开发与联调/开发联调记录.md` 写“外部接口接入清单”小节；接口复杂时才单独形成 `外部接口接入清单.md`。至少确认：

1. 接口文档版本。
2. demo 代码。
3. 测试环境地址。
4. 账号、证书、密钥、签名、加密、Base64、摘要规则。
5. 请求外层协议和业务报文结构。
6. 响应外层协议和业务响应结构。
7. 错误码、超时、重试、幂等、补偿规则。
8. 敏感配置来源。
9. 真实集成测试默认关闭，只有显式开关才允许执行。

## 7. 安全红线

以下问题一律优先修正：

1. 代码、SQL、测试用例、配置模板里硬编码账号、密码、密钥、证书密码、token。
2. 用户输入拼接 SQL。
3. 日志打印敏感信息。
4. 商户权限绕过。
5. 外部真实接口测试默认自动执行。
6. 列表接口返回请求报文、明细快照等大字段。

## 8. 已确认事项怎么处理

确认冻结台账是后续阶段的事实来源。

1. 已冻结事项不得重复提问。
2. 已冻结事项不得被 AI 自行推翻。
3. 如果代码现状、接口文档或业务反馈与冻结结论冲突，必须登记变更记录。
4. 方案设计、任务拆分、开发、测试都必须引用冻结台账。

## 9. 完成前必须验证

AI 不能只因为代码写完就宣称完成。完成前至少说明：

1. 编译是否通过。
2. 自动化测试是否通过。
3. 关键接口或页面是否验证。
4. 外部接口是否只在显式开关下测试。
5. 权限、金额、状态、幂等、安全红线是否覆盖。
6. 哪些验证因环境限制无法执行，替代验证是什么。

## 10. 最小执行口令

日常让 AI 接手一个阶段时，使用这个口令：

```text
请继续当前需求。

先读取：
1. 根目录 README.md
2. 02-资产层/README.md
3. 当前需求 STATUS.md
4. 当前阶段已有文档
5. 02-资产层/06-Superpowers技能方法/00-技能选择总入口.md

按当前阶段推进。
已冻结事项不得重复提问。
先选择当前阶段对应的 Superpowers 方法，再执行。
编码前必须在开发联调记录中补齐代码理解、实施落点清单，并引用任务拆分中的任务级验证目标。
涉及外部接口时必须补外部接口接入清单小节。
不得硬编码敏感信息，不得拼接 SQL，不得跳过完成前验证。
```
