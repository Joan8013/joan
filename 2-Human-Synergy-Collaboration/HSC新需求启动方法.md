# HSC 新需求启动方法

以后启动一个新需求，不要直接说“帮我写代码”。按 HSC（Human-Synergy Collaboration）人机协同开发框架的顺序开始，最稳。

## 第一步：建需求工作台

从标准模板复制一套目录：

```text
03-需求工作台/REQ-XXX - 需求名称/
  00-原始材料
  01-需求澄清/需求澄清.md
  02-影响分析/影响分析.md
  03-方案设计/方案设计.md
  04-任务拆分/任务拆分.md
  05-开发与联调/开发联调记录.md
  06-测试与验收/测试验收.md
  07-复盘沉淀/复盘沉淀.md
  STATUS.md
```

默认规则：一阶段一主文档，`STATUS.md` 只做总控，不默认创建 `v1/v2/v3`，不默认拆出多份确认文档。

## 第二步：放原始材料

把需求文档、截图、接口文档、SQL、原型、聊天记录、demo、测试环境说明都放到：

```text
00-原始材料
```

如果是三方接口，必须同时放：

```text
接口文档
demo
测试环境信息
证书/认证说明
```

## 第三步：对 AI 发启动口令

推荐直接这样说：

```text
启动新需求：REQ-XXX - XXX功能。

需求工作台路径：
E:\\CodexSpace\ETC-AI-ReqFlow-Structured\03-需求工作台\REQ-XXX - XXX功能

请按结构化流程执行：
1. 先读取根目录 README.md。
2. 再读取 02-资产层/README.md。
3. 再读取 02-资产层/06-Superpowers技能方法/00-技能选择总入口.md。
4. 再读取当前需求的 00-原始材料 和 STATUS.md。
5. 第一阶段只做需求澄清和确认冻结台账。
6. 不写代码，不进入方案设计。
7. 已确认事项写入 01-需求澄清/需求澄清.md 的确认冻结台账小节，后续阶段不得重复提问。
```

## 第四步：按阶段推进

阶段推进顺序固定为：

```text
00-原始材料
-> 01-需求澄清
-> 02-影响分析
-> 03-方案设计
-> 04-任务拆分
-> 05-开发与联调
-> 06-测试与验收
-> 07-复盘沉淀
```

每个阶段只补当前阶段主文档。复杂专题可以单独建文档，但不能把默认流程拆成一堆必维护文件。

## 第五步：编码前必须过门禁

进入 `05-开发与联调` 前，先让 AI 在 `开发联调记录.md` 补齐编码前门禁：

1. 引用 `01-需求澄清/需求澄清.md` 的冻结结论。
2. 说明代码理解：模块、包、参考类、代码风格。
3. 明确实施落点：文件、接口、表、配置、测试。
4. 引用 `04-任务拆分/任务拆分.md` 的任务级验证目标。
5. 涉及外部接口时补外部接口接入清单。

没有这些内容，不进入正式编码。

## 第六步：TDD 和验收的边界

TDD 不是验收阶段才做。

1. `04-任务拆分` 定义验收断言、任务级验证目标和 TDD 适用性。
2. `05-开发与联调` 按任务执行 TDD 红-绿-重构；不适合 TDD 的任务记录原因和替代验证。
3. `06-测试与验收` 记录测试结果、完成前验证和验收结论。

一句话：新需求先建工作台、放材料、跑澄清和冻结；没有冻结结论、代码理解、实施落点和任务级验证目标，不进入编码。
