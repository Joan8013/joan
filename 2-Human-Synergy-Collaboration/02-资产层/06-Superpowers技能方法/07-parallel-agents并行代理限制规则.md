# parallel-agents：并行代理限制规则

对应 Superpowers：

1. `subagent-driven-development`
2. `dispatching-parallel-agents`

## 1. 允许使用条件

同时满足：

1. 需求口径已冻结。
2. 方案边界清楚。
3. 任务可拆且相互独立。
4. 每个子任务有明确输入和输出。
5. Owner 能统一整合上下文。
6. 不涉及未确认的资金、状态、权限、生产数据口径。

## 2. 适合场景

1. 多模块影响分析。
2. 大范围代码阅读。
3. 多个相对独立页面或接口改造。
4. 文档资产批量整理。
5. 测试场景补充。

## 3. 不适合场景

1. 需求口径未冻结。
2. 核心资金链路高度耦合。
3. 状态流转复杂且未评审。
4. 单个小修复。
5. 需要统一业务判断的任务。

## 4. 使用规则

1. 子代理只做子任务，不做最终裁决。
2. 子代理产物必须回到 Owner 统一整合。
3. 子代理发现风险必须标记，不得自行解决高风险口径。
4. 最终输出必须附带 AI 自我评估。
5. 每个子代理的任务边界应控制在 2 小时内可完成的分析或实现工作，超过则继续拆分子任务。
6. 不自行补全金额、状态、清分、结算、发票、权限、生产数据规则。
