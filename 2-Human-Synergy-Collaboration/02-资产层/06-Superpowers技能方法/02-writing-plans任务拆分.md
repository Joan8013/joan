# writing-plans：任务拆分

## 1. 适用场景

1. 方案已经基本确认。
2. 需要把需求拆成可执行任务。
3. 需要明确开发顺序、依赖、系统级验收断言、任务级验证目标和 TDD 适用性。

## 2. 操作步骤

1. 读取需求澄清、影响分析和方案设计。
2. 拆分任务包。
3. 标记任务依赖和并行关系。
4. 为每个任务定义完成标准。
5. 为每个任务定义验证目标和建议验证层级。
6. 标记任务是否适合 TDD，并说明不适合原因和替代验证方式。
7. 输出系统级验收测试清单。

## 3. 输出产物

1. 任务拆分清单。
2. 任务依赖关系。
3. 每个任务的完成标准。
4. 系统级验收测试。
5. 任务级验证目标和 TDD 适用性。
6. 是否可以进入开发与联调。

## 4. 禁止事项

1. 不用代码步骤替代业务任务包。
2. 不在需求口径未冻结时拆实现细节。
3. 不把排期承诺伪装成 AI 估算。
4. 不把本阶段当成完整 TDD 执行。
5. 不自行补全金额、状态、清分、结算、发票、权限、生产数据规则。

## 5. 不适合 TDD 的典型任务

以下任务可以标记为“非 TDD”，但必须写明替代验证方式：

1. UI 样式调整。
2. 纯配置变更。
3. 简单数据迁移脚本。
4. 第三方 SDK 集成且无稳定可控返回值。
5. 仅文档或说明性材料调整。

替代验证方式可以包括人工验收、配置比对、SQL 预演、集成测试或日志/监控验证。
