# 技能选择总入口

对应 Superpowers：`using-superpowers`

## 1. 目标

在当前阶段选择合适的 AI 执行方法，避免 AI 直接凭提示词自由发挥。

## 2. 场景到技能快速查找表

用法：找到当前面临的场景，直接使用对应技能卡。

| 当前场景 | 使用技能 | 说明 |
| --- | --- | --- |
| 需求描述模糊，不知道从哪里下手 | `01-brainstorming` | 先澄清再行动，不猜 |
| 需要评估多个技术方案优劣 | `01-brainstorming` | 系统化对比，不凭感觉 |
| 需要梳理影响范围，如模块、接口、数据库、外部系统 | `01-brainstorming` | 结构化探索影响面 |
| 方案已定，需要拆成可执行任务 | `02-writing-plans` | 拆到可执行、可验证 |
| 准备开始写某个任务代码 | `03-test-driven-development` | 红-绿-重构，任务级测试先行 |
| 代码跑不通，出现异常或报错 | `04-systematic-debugging` | 先定位根因，再动手修 |
| 联调发现对方接口行为不符合预期 | `04-systematic-debugging` | 判断是对方、自己还是文档口径问题 |
| CI 流水线失败，如编译、测试、扫描失败 | `04-systematic-debugging` | 定位失败原因，针对性修复 |
| 某个任务代码写完，准备提交评审 | `05-code-review` | 先自审，再发起评审 |
| 收到架构师、测试负责人或同事评审意见 | `05-code-review` | 逐条处理，阻塞项必须闭环 |
| 准备宣布某个开发任务完成 | `06-verification-before-completion` | 完成前验证，不验证不宣称完成 |
| 准备判断整个需求是否可进入上线准入 | `06-verification-before-completion` | 验证材料齐备后，进入上线准入强门禁 |
| 多个任务互不依赖，需要并行推进 | `07-parallel-agents` | 先确认无依赖，再限制并行 |
| 大任务需要拆成多个子任务并行分析或实现 | `07-parallel-agents` | 控制任务边界，Owner 统一整合 |
| 以上场景都不匹配 | 先查流程阶段，再选对应技能 | 不要强行套用技能 |

## 3. 选择顺序

1. 确认当前需求阶段。
2. 确认风险等级。
3. 确认检查点或门禁是否满足。
4. 选择对应技能。
5. 执行后把产物写回需求工作台。
6. AI 参与关键产物时附带 AI 自我评估。

## 5. 禁止顺序

1. 没有澄清就写计划。
2. 没有影响分析就写方案。
3. 没有方案边界就拆代码任务。
4. 没有任务级测试目标就进入 TDD。
5. 没有失败测试就先写实现。
6. 没有根因就先修 Bug。
7. 没有完成前验证就宣称完成。
