# code-review：评审闭环

对应 Superpowers：

1. `requesting-code-review`
2. `receiving-code-review`

## 1. 发起评审前

必须准备：

1. 需求摘要。
2. 风险等级。
3. 方案关键点。
4. 代码改动清单。
5. 测试执行结果。
6. 已知风险。
7. 需要重点 Review 的问题。

## 2. 收到评审意见后

按类型分类：

| 类型 | 处理方式 |
| --- | --- |
| 必须修复 | 修改代码并重新验证 |
| 需要解释 | 补充设计依据或代码说明 |
| 需要业务确认 | 提交产品或技术项目负责人 |
| 可后置 | 记录后续计划和风险接受 |

## 3. 禁止事项

1. 不忽略评审意见。
2. 不把代码 Review 当作业务口径 Review。
3. 不在评审意见未闭环时进入上线准入。
4. 不用 AI 自评替代人工 Review。
5. 不把涉及资金、状态、权限、生产数据口径的评审意见在代码层直接闭环；必须回到产品经理、架构师或技术项目负责人处确认口径。
