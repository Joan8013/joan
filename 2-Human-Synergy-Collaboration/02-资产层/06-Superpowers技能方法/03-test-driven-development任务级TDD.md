# test-driven-development：任务级 TDD

## 1. 适用场景

1. 开发任务边界清楚。
2. 任务级验证目标明确，并已判断适合 TDD。
3. 业务口径已确认。
4. 代码位置和同类实现已阅读。

## 2. 操作步骤

每个开发任务内部执行：

```text
红：先写一个失败的可执行断言或测试
绿：写最少代码让测试通过
重构：优化结构，并保持测试通过
```

TDD 不等同于单元测试。红阶段优先选择能最快反馈风险的验证层级，可以是单元测试、接口测试、集成测试、组件测试或页面行为测试。

## 3. 记录要求

每个任务记录：

1. 失败测试是什么。
2. 最小实现是什么。
3. 重构改了什么。
4. 测试命令和结果。
5. 无法 TDD 的原因和替代验证方式。
6. 覆盖率结果或未统计原因。

覆盖率目标按团队 CI 质量门禁或风险等级规则执行；若尚未定义，应在任务拆分阶段明确。

## 4. 禁止事项

1. 不把测试计划当成 TDD。
2. 不先写实现再补测试冒充 TDD。
3. 不为了通过测试而降低断言。
4. 不删除失败测试来宣称通过。
5. 不在业务口径未确认时写实现。
6. 不自行补全金额、状态、清分、结算、发票、权限、生产数据规则。
