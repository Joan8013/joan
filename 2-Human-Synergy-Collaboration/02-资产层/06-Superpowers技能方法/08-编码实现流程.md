# 08-编码实现流程

对应 Superpowers：`test-driven-development` + `requesting/receiving-code-review` + `verification-before-completion` + `systematic-debugging`

## 1. 目标

用 Superpowers 的**纪律**驱动"怎么写得好"，用项目**编码约定**保证"具体怎么写对"。
本卡不重复通用提示词，只把已有技能串成一条编码链，并挂接编码约定。

## 2. 前置（编码前门禁，缺一不进）

1. 需求已冻结（`01-需求澄清` 确认冻结台账）。
2. 「编码前理解确认」已人工通过（`02-模板库/05` + `人类快速确认指南` 关口二）。
3. 已读 `02-资产层/07-编码约定/编码约定.md`，并读过 2 个同域同类实现。
4. 任务级"首个失败断言"已在 `04-任务拆分` 定义。

## 3. 编码链（每个任务内部执行）

```text
① 红  test-driven-development：先写失败测试，跑出红灯并留证据（先于实现）
② 绿  写最小实现让测试通过
        ↳ 实现全程遵循「编码约定」：分层/统一响应/BigDecimal/权限从token取/幂等/Feign结构/不打敏感日志/复用common-*
③ 重构 保持测试绿的前提下优化结构
④ 自审 requesting-code-review：对照编码约定 + 安全红线自审（金额/权限/幂等/SQL/大字段）
⑤ 评审 收到意见用 receiving-code-review 逐条闭环，阻塞项必须关闭
⑥ 验证 verification-before-completion：编译+测试+覆盖率+变异，不验证不宣称完成
   （出 bug 时用 systematic-debugging 先定位根因再改，不乱试）
```

## 4. 记录

- 红-绿-重构 + 红灯证据：写入 `05-开发与联调/开发联调记录.md` 的任务 TDD 记录。
- 遵循编码约定情况：在自审中对照 `编码约定.md` 各节；违例先修。
- 完成前验证：写入 `06-测试与验收`，并按测试可信度报告给证据。

## 5. 禁止

1. 未过编码前门禁就写实现。
2. 先写实现再补测试冒充 TDD。
3. 沿袭 `编码约定.md` §12 的技术债（如注释掉 `@PreAuthorize`）。
4. 违反安全红线（硬编码密钥、拼接 SQL、打印敏感、权限绕过）。
5. 未做完成前验证就宣称完成。
