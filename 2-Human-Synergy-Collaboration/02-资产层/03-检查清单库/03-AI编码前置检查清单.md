# AI 编码前置检查清单

AI 或开发人员开始改代码前必须完成本清单。

## 1. 规则阅读

- [ ] 已阅读当前工作区 AGENTS.md。
- [ ] 已阅读真实项目代码仓库 AGENTS.md。
- [ ] 已阅读需求 STATUS.md。
- [ ] 已阅读方案设计和任务拆分。

## 2. 模块定位

- [ ] 已确认前端入口。
- [ ] 已确认后端模块。
- [ ] 已确认 API 契约位置。
- [ ] 已确认数据库影响。
- [ ] 已确认配置影响。

## 3. 同类实现与编码约定

- [ ] 已阅读 `02-资产层/07-编码约定/编码约定.md`。
- [ ] 至少阅读 2 个同模块同类 Controller/Service/Mapper/前端页面。
- [ ] 已确认返回结构和异常处理风格。
- [ ] 已确认分页、导出、下载、权限写法。
- [ ] 已确认 MyBatis XML 风格。
- [ ] 已知晓并避免 `编码约定.md` §12 的已知技术债。

## 4. 安全底线

- [ ] 不硬编码账号、密码、Token、密钥、证书路径。
- [ ] SQL 使用参数绑定，不拼接用户输入。
- [ ] 金额、税额、费率使用 BigDecimal。
- [ ] 权限和数据范围已确认。
- [ ] 文件下载无路径穿越风险。

## 5. TDD

- [ ] 已先定义测试断言。
- [ ] 适合 TDD 的任务已写出首个失败断言/测试设想。
- [ ] 标记"不适合 TDD"的任务已填写原因并经人工确认，未由 AI 自行跳过。
- [ ] 明确哪些测试自动化。
- [ ] 明确哪些测试人工验收。
- [ ] 已知晓：红阶段需保留失败测试的实际运行输出，以及能证明其先于实现的提交号/时间戳。

## 6. 准出

- [ ] 可以开始编码。
- [ ] 仍存在的风险已记录。
