# 验收清单

用于"测试与验收"阶段的人工验收，一页勾选。配套 `01-流程层/验收快速指南.md`。
正常需求约 10~15 分钟完成。**任一 No-Go 项不通过即不予验收。**

## 1. 业务验收（对着验收标准逐条）

- [ ] `04-任务拆分` 的每条验收标准(AC)都有对应且通过的测试或演示。
- [ ] 实现结果符合业务意图，无偏离、无擅自加/减功能。
- [ ] 确认人（需求/业务负责人）：____

## 2. 测试可信度（看 4 项，不读测试代码）

- [ ] AC↔测试映射：每条 AC 均被覆盖。
- [ ] 红灯证据：关键测试先红后绿（非事后补的橡皮图章）。
- [ ] 变异测试分数达阈值（建议核心包 ≥70%）。
- [ ] 假测试自检通过：无空断言、断言未降低、外部已打桩。
- [ ] 确认人（测试负责人）：____

## 3. 高风险口径抽查（只查冻结口径，A 类必做）

- [ ] 金额/尾差口径与冻结台账一致。
- [ ] 清分/结算/划账口径与冻结台账一致。
- [ ] 幂等键与重复处理与冻结口径一致。
- [ ] 权限与数据范围（含商户隔离）正确。
- [ ] 确认人（财务/结算负责人）：____

## 4. 主链路走查

- [ ] 核心正常流跑通（演示/E2E/黄金文件）。
- [ ] 至少 1 条关键异常流表现正确。
- [ ] 确认人（需求负责人）：____

## 5. Go/No-Go（上线前）

- [ ] 已过 `05-上线前检查清单`（版本/DB/配置/回滚/审批）。
- [ ] 监控与排查入口已就绪。
- [ ] Go/No-Go 结论：____（上线负责人：____）

## No-Go 硬条件（任一命中即不通过）

1. 有 AC 未被测试覆盖。
2. 测试可信度存疑（变异不达标 / 无红灯 / 假测试自检未过）。
3. A 类高风险口径与冻结台账不一致或未人工确认。
4. 上线前检查清单有未关闭阻塞项。

## 验收结论

`通过` / `有条件通过（列条件）` / `不通过（列 No-Go 项）`
