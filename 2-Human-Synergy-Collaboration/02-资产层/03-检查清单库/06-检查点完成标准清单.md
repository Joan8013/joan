# 检查点完成标准清单

本清单用于需求 Owner 判断检查点是否“做完且合格”。

检查点不是审批会，而是防止上下文缺失和风险遗漏的质量检查。

## 1. 通用标准

所有检查点必须满足：

- [ ] 对应阶段产物已写入需求工作台。
- [ ] `STATUS.md` 已更新当前阶段。
- [ ] 已记录已确认事项。
- [ ] 已记录待确认事项，并标记是否阻塞。
- [ ] 已记录当前风险。
- [ ] 已记录下一步动作。
- [ ] 阶段交接卡已填写。
- [ ] AI 参与关键产物时，已附带 AI 自我评估。
- [ ] AI 自我评估中的高风险和不确定事项已进入待确认事项或风险台账。
- [ ] 涉及资金、权限、生产数据、外部接口时，已显式标记。
- [ ] 未确认事项没有被默认假设。

## 2. 需求澄清检查点

完成且合格必须满足：

- [ ] 业务目标明确。
- [ ] 本期范围明确。
- [ ] 非范围明确。
- [ ] 核心业务口径明确。
- [ ] 风险等级已复核。
- [ ] A 类触发条件已检查。
- [ ] 待确认事项已形成台账。
- [ ] 阻塞事项已标记。
- [ ] 产品经理确认关键业务口径。

不合格表现：

- 关键业务规则悬空。
- 范围和非范围模糊。
- A 类风险未识别。
- 未确认事项被下阶段默认假设。

## 3. 影响分析检查点

完成且合格必须满足：

- [ ] 前端影响已分析。
- [ ] 后端影响已分析。
- [ ] 数据库影响已分析。
- [ ] 外部接口影响已分析。
- [ ] 权限和数据范围影响已分析。
- [ ] 定时任务和批处理影响已分析。
- [ ] 资金、状态、清分、结算、发票、对账影响已分析。
- [ ] QPS、吞吐量、核心链路响应时间影响已分析。
- [ ] 超时、重试、熔断、限流、系统启动、关键初始化影响已分析。
- [ ] 日志、监控指标、链路追踪、告警规则影响已分析。
- [ ] 已列出主要代码路径。
- [ ] 已阅读同类实现。
- [ ] 风险和待确认事项已记录。

不合格表现：

- 只写泛泛影响，没有代码路径。
- 未读真实代码。
- 未分析权限或数据范围。
- 未分析定时任务、外部接口或数据一致性。
- 未分析可用性或可观测性影响。

## 4. 任务拆分检查点

完成且合格必须满足：

- [ ] 任务拆分到可执行粒度。
- [ ] 每个任务有负责人或角色。
- [ ] 每个任务有完成标准。
- [ ] 任务依赖关系明确。
- [ ] 并行和串行关系明确。
- [ ] 系统级验收测试清单已形成。
- [ ] 每个任务的验证目标和 TDD 适用性已定义。
- [ ] 不适合 TDD 的任务已说明原因和替代验证方式。

不合格表现：

- 任务过大，不可执行。
- 任务无法分配。
- 没有完成标准。
- 没有验收测试或任务级验证目标。

## 5. 测试策略检查点

完成且合格必须满足：

- [ ] 主链路测试明确。
- [ ] 异常链路测试明确。
- [ ] 权限和数据范围测试明确。
- [ ] 幂等和重复执行测试明确。
- [ ] 外部接口失败和超时测试明确。
- [ ] 回归测试范围明确。
- [ ] 测试数据准备方式明确。
- [ ] 自动化测试和人工验收边界明确。
- [ ] A 类需求测试负责人已确认关键测试策略。

不合格表现：

- 只测主流程。
- 异常、权限、幂等缺失。
- 没有测试数据准备方式。
- 无法支撑上线风险判断。

## 6. 不合格处理

检查点不合格时：

1. 不进入下一阶段。
2. 补充缺失材料。
3. 必要时退回上一阶段。
4. 阻塞事项提交对应角色确认。
5. 如需带风险推进，必须记录风险接受人、接受理由和补偿措施。
