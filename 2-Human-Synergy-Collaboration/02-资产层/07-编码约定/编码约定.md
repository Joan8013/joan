# extend_platform 编码约定

> 本约定从**真实代码**归纳（见 `代码规范提取`），是"本项目具体怎么写"的事实层。
> "怎么写得好"的纪律（先测后码、评审、完成前验证）由 `06-Superpowers技能方法/08-编码实现流程.md` 负责。
> 写代码前先读本约定；Cursor 会通过 `.cursor/rules/coding-standard.mdc` 自动加载要点。

## 0. 总原则

1. **先读 2 个同域同类实现再动手**，保持与现有代码一致，不引入陌生风格。
2. 复用 `common-*` 已有能力（见 §10），不重复造轮子。
3. 遵守安全红线（§9、§11）与人工兜底口径（金额/清分/幂等/权限须人工确认）。

## 1. 包与分层

**DO**
- 运营端 Controller：`com.etcplus.system.manage.<域>.controller`，路径如 `/reconBill`。
- 商户端 Controller（新）：`com.etcplus.system.split.merchant.<域>.controller`，类名 `Mh*`，路径 `/mhApi/*`。
- 共享业务：`com.etcplus.system.business.<域>`，含 `domain / mapper / service / service/impl`。
- MyBatis XML：`resources/mapper/system/business/<域>/`（商户侧 `resources/mapper/split/merchant/<域>/`）。
- Feign 契约放 `etcplus-api-exchange`（仅接口/DTO/Fallback）；三方实现放 `etcplus-exchange`。
- 命名后缀沿用：入参 `XxxRequest`/`XxxReq`、视图 `XxxVO`、查询 `XxxQuery`、导出 `XxxExport`。

**DON'T**
- Controller 里写业务逻辑或 SQL（业务放 Service，SQL 放 Mapper/XML）。
- 把三方调用逻辑写进 system 业务模块（应走 Feign → exchange）。

## 2. 统一响应

**DO**
- Controller 继承 `BaseController`。
- 分页：`startPage()` + `getDataTable(list)` 返回 `TableDataInfo`。
- 单对象/操作：`AjaxResult.success(data)` / `AjaxResult.error(msg)`；影响行数用 `toAjax(rows)`。
- 服务间/Feign：返回 `R<T>`（不要用 `AjaxResult`）。
- 导出：`void` + `HttpServletResponse` + `ExcelUtil`，不走 JSON 包装。

**DON'T**
- 自定义临时响应结构（除既有 `etcplus-trans` 的 `DefaultResponse` 等历史约定外）。

## 3. 异常处理

**DO**
- 业务可预期错误抛 `BaseException("中文提示")`（部分 settle 域用 `CustomException`，与所在域保持一致）。
- 写操作加 `@Transactional(rollbackFor = Exception.class)`。
- 交给全局 `GlobalExceptionHandler` 统一转 `AjaxResult.error`，不在 Controller 里吞异常。

**DON'T**
- 空 `catch` 或吞掉异常继续执行；把底层异常直接抛给前端而无中文提示。
- 用 `throw new RuntimeException(e)` 掩盖可预期业务错误（应转 `BaseException`）。

## 4. 金额 / BigDecimal

**关键：本项目按域有两种金额风格，改哪个域就跟哪个域，不要混用。**

| 域 | 存储/传输 | 计算 |
| --- | --- | --- |
| 对账 `ReconBill` | `Long`（分） | `BigDecimal` 中间算 → `longValue()` 存分，`RoundingMode.HALF_UP` |
| 发票 `ReconBillInvoice` | `BigDecimal`（元） | `divide(..., 2, HALF_UP)`，scale 2 |
| 结算 `EtcplusSettleDetail` | `BigDecimal` 为主，部分 fee `Long` | 导出 `/100` 转元；`compareTo` 比较 |

**DO**
- 金额计算一律用 `BigDecimal`；比较用 `compareTo` / `isEqualByComparingTo`。
- 分↔元转换集中在明确的方法/SQL（`round(#{fen}/100,2)`），并注明单位。
- 新增金额字段优先 `BigDecimal`（元，明确 scale）。

**DON'T**
- 用 `double`/`float` 参与任何金额运算。
- 用 `equals` 比较 BigDecimal（标度不同会误判）。
- 在同一条链路里混用"分"和"元"而不标注。

## 5. MyBatis 风格

**DO**
- `namespace` = Mapper 接口全限定名；`resultMap` id = `{Entity}Result`；SQL 片段 `select{Entity}Vo`。
- 方法名：`select{Entity}List/ById`、`insert/update/delete{Entity}`。
- 动态条件用 `<where>` + `<if test="x != null and x != ''">`；日期范围用 `params.beginXxx/endXxx`。
- 插入用 `<trim>` 动态列 + `useGeneratedKeys="true" keyProperty="id"`。
- 参数一律 `#{}` 绑定；并发更新用 `where id=? and status=?` 或 `FOR UPDATE`。
- 商户侧查询用 `merchant_id = #{merchantId}` 精确匹配（不用 like）。

**DON'T**
- 拼接用户输入到 SQL（`${}` 仅限排序等受控场景，且过 `SqlUtil` 防注入）。
- 列表 `SELECT *`；列表返回 `request_payload`、`item_detail_payload` 等大字段。

## 6. 权限与数据范围（含商户隔离）

**DO**
- 运营接口加 `@PreAuthorize(hasPermi="module:resource:action")`；商户接口加 `@MhPreAuthorize`。
- 商户端 `merchantId` **一律从 token 取**（`MhTokenService.getLoginUserMerchantId()`）并覆盖入参，不信任前端传入。
- Service 层对资源做所有权校验：`if (!merchantId.equals(entity.getMerchantId())) throw new BaseException("无权操作…")`。
- 需要部门数据范围时用 `@DataScope`/`@MhDataScope`。

**DON'T**
- 直接用前端传入的 `merchantId` 查询。
- 新代码把 `@PreAuthorize` 注释掉（见 §12 技术债，勿沿袭）。

## 7. 幂等与分布式锁

**是否加幂等兜底：先评估，别默认。** 幂等兜底有成本（DB 唯一键、查重、行锁均影响写性能），
**不要给所有接口无脑加幂等**。写"创建持久化业务记录/触发下游动作/资金"的接口时，
**主动提醒并评估是否需要服务端技术幂等兜底，由架构师判断决定**；判定结论记入方案设计决策项。

判定参考（满足其一才考虑加）：

| 需要幂等兜底 | 通常不需要 |
| --- | --- |
| 请求可能被网络重试/并发/直连绕过前端 | 纯查询（GET）、天然幂等（状态 CAS/覆盖式更新） |
| 重复会造成业务后果（重复工单、重复扣款、重复推送、重复开票） | 重复无副作用或成本可忽略 |
| 创建工单/订单、资金操作、触发外部/下游 | 内部低频、无持久副作用的操作 |

**DO（确认需要幂等后）**
- 用业务幂等键：`clientRequestId`/交易流水号 + DB 唯一键（如开票申请 `(recon_bill_id, biz_nature, client_request_id)`）。
- 并发关键路径用行锁（`selectXxxByIdForUpdate`）或状态 CAS（`update … where status=?`）。
- 唯一约束兜底：`catch (DuplicateKeyException)` 转业务码或静默返回。
- 需要跨节点互斥时用 `@RedisDistributedLock`（common-distributedlock）。

**DON'T**
- 资金操作（清分/结算/开票/退款）在**已判定需要**时不做幂等。
- 判定需要幂等却只靠应用层查重而无 DB 唯一键兜底。
- 为"看起来更安全"给所有接口默认加幂等，牺牲性能。

## 8. Feign / exchange 结构

**DO**：`RemoteXxxService(@FeignClient, contextId 唯一, value=ServiceNameConstants.XXX, fallbackFactory=...)` → exchange `Controller`(路径与 Feign 一致) → `ServiceImpl` → `XxxClient`。契约仅依赖 `common-core`，统一返回 `R<T>`。

**DON'T**：Feign 契约里放实现或依赖业务模块；漏配 `fallbackFactory`/`contextId`。

## 9. 日志与脱敏

**DO**
- 操作审计用 `@Log`/`@MhLog`/`@RaLog`；业务日志用 SLF4J，关键节点可追踪（带业务键）。
- 打印前对敏感字段脱敏（车牌可用 `PlateNumberDesensitizeUtil`）。

**DON'T**
- 日志打印密码、密钥、证书密码、token、完整报文等敏感信息。

## 10. 复用 common-*（勿重复造轮子）

`SecurityUtils`(取用户/token) · `StringUtils` · `DateUtils` · `BeanUtils`(属性拷贝) · `ExcelUtil/EasyExcelUtil`(导出) · `RedisService` · `BaseController/AjaxResult/TableDataInfo/R/BaseEntity` · `SqlUtil`(排序防注入)。需要某能力先在 common-* 找，找不到再写。

## 11. 安全红线（一票否决）

1. 硬编码账号/密码/密钥/证书密码/token（用环境变量或配置中心）。
2. 用户输入拼接 SQL。
3. 日志打印敏感信息。
4. 商户权限绕过（未从 token 取 merchantId）。
5. 外部真实接口测试默认自动执行（须显式开关，如 `LEQ_INTEGRATION_TEST=true`）。
6. 列表接口返回大字段（请求报文/明细快照）。

## 12. 已知技术债与风险（新代码不得沿袭）

以下是提取时发现的现状问题，**新代码必须避免，改到相关处应顺手修正或登记**：

1. 不少运营 Controller 的 `@PreAuthorize` 被注释 → 新接口必须启用权限注解。
2. 多处 XML 的 `${params.dataScope}` 数据权限 SQL 被注释 → 涉及数据范围时确认切面生效。
3. `LogAspect` 超长结果 `substring` 未赋值，可能全量入库 → 涉及日志时注意。
4. `@RedisDistributedLock` 模块存在但业务未使用 → 需要跨节点互斥时正式启用。
5. 未配置 Checkstyle/SpotBugs → 见 §13 建议引入。

## 13. 静态检查门禁（Checkstyle + SpotBugs + 安全扫描）

当前仅有 Enforcer/JaCoCo/前端 ESLint，后端缺静态检查。配置模板已就绪，见
`02-资产层/05-测试资产库/后端/pom模板/`：
- `静态检查配置.md`：插件配置、`-Pquality-gate` Profile、**分阶段落地**（遗留库先报告后卡门、只卡新代码）。
- `checkstyle.xml` / `checkstyle-suppressions.xml`：规则集（聚焦真问题，含金额/空catch/字符串==/禁 System.out）+ 存量豁免。
- `spotbugs-exclude.xml`：排除误报；搭配 **find-sec-bugs** 扫 SQL 注入、硬编码密钥等（对齐 §11 安全红线）。

命令：`mvn -Pquality-gate verify`。稳定卡门后接入 `03-检查清单库/04-AI完成前质量门禁清单.md`。
