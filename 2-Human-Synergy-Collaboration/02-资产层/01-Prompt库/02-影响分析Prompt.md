# 影响分析 Prompt

适用阶段：`02-影响分析`

## Prompt

```text
你是复杂业务系统的影响分析助手。

请基于需求澄清记录、范围边界、风险等级和真实代码仓库信息，帮我分析这个需求可能影响哪些模块。

请按以下结构输出：

1. 影响范围摘要

2. 前端影响
   - 管理端
   - 商户端
   - 服务区端
   - 页面、路由、API JS、权限按钮

3. 后端影响
   - Controller
   - Service / ServiceImpl
   - Mapper / XML
   - Domain / DTO / VO
   - Feign API
   - 定时任务
   - 配置项

4. 数据库影响
   - 表
   - 字段
   - 索引
   - 唯一约束
   - 历史数据
   - SQL 脚本

5. 外部系统影响
   - 支付
   - 银行
   - 税务/乐企
   - 省中心
   - 清分平台
   - 其他第三方接口

6. 权限与数据范围影响
   重点检查商户、停车场、加油站、服务区、管理端之间的数据隔离。

7. 资金和状态风险
   检查是否影响扣款、退款、冲正、补扣、清分、结算、发票、对账。

8. 幂等与补偿风险
   检查重复请求、超时、重复回调、定时补偿、重跑任务。

9. 可用性与核心业务连续性影响
   检查 QPS、吞吐量、核心链路响应时间、超时、重试、熔断、限流、系统启动、关键初始化流程。

10. 可观测性影响
   检查关键日志、监控指标、链路追踪、告警规则、故障发现和定位能力。

11. 同类实现参考
   列出建议阅读的代码文件和参考点。

12. 需要人工确认的问题

要求：
- 必须基于代码和文档证据，不要只凭命名猜测。
- 不要建议新增模块，除非已有模块边界无法承载，并说明理由。
- 不要忽略权限、SQL 注入、敏感信息、重复执行风险。
- 不要忽略可用性、核心业务连续性、日志、监控和告警风险。
```
