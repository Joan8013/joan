# 00-治理层

治理层回答：

```text
什么能让 AI 参与，什么必须人来决定。
```

治理层是所有需求共同遵守的底线，不应该被复制到每一条需求里。

在 HSC 人机协同开发框架中，治理层负责回答“人和 AI 的权责边界在哪里”。

## 1. 职责

1. 定义人机协同开发的目标。
2. 定义风险分级和 AI 适用边界。
3. 定义团队角色职责。
4. 定义人工兜底规则。
5. 定义不可跳过的高风险关口。

## 2. 输入

| 输入 | 来源 |
| --- | --- |
| 团队交付目标 | 负责人、项目管理 |
| 业务风险类型 | 产品、架构、开发、测试、运营、财务 |
| 历史事故和返工案例 | 复盘沉淀、线上问题 |
| 组织职责边界 | 团队管理和协作约定 |

## 3. 输出

| 输出 | 用途 |
| --- | --- |
| AI 适用边界 | 判断 AI 能做什么、不能做什么 |
| 风险分级规则 | 判断需求是否需要更严格评审 |
| 角色职责 | 明确谁确认、谁实现、谁测试、谁兜底 |
| 人工兜底规则 | 防止金额、状态、幂等、对账等关键口径被 AI 单方面决定 |

## 4. 边界

治理层不写具体需求方案，不写某条需求的任务拆分，也不沉淀通用模板。

治理层只定义长期稳定的原则。如果某个内容只对一条需求有效，应放入需求工作台。
