# 04-度量层

度量层回答：

```text
这套体系到底有没有提效。
```

度量层不追求复杂报表，先追求持续记录、可复盘、可反哺。

## 1. 职责

1. 定义 HSC 人机协同开发效果指标。
2. 记录每条需求的关键度量。
3. 汇总返工、漏测和提前发现风险。
4. 反哺治理层、流程层和资产层。

## 2. 输入

| 输入 | 来源 |
| --- | --- |
| 需求耗时 | 需求工作台 |
| 改动点定位耗时 | 需求工作台、开发记录 |
| 返工次数 | Review、联调、测试、上线后问题 |
| 测试遗漏数 | 测试和验收记录 |
| 高风险提前发现数 | 澄清、影响分析、Review |

## 3. 输出

| 输出 | 去向 |
| --- | --- |
| 度量记录 | 团队复盘 |
| 改进建议 | 治理层、流程层、资产层 |
| 资产沉淀建议 | 资产层 |
| 流程调整建议 | 流程层 |

## 4. 边界

度量层不保存单条需求的完整过程文档，只保存指标、结论和改进建议。

详细过程材料仍保留在需求工作台。

| --- | --- |
