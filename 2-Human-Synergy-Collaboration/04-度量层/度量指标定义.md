# 度量指标定义

## 1. 核心指标

| 指标 | 定义 | 记录方式 |
| --- | --- | --- |
| 需求分析耗时 | 从拿到原始需求到形成澄清结论的时间 | 小时或人天 |
| 改动点定位耗时 | 从开始分析代码到形成影响点清单的时间 | 小时或人天 |
| 返工次数 | 因需求理解、方案、实现、测试遗漏导致的重复修改次数 | 次 |
| 测试遗漏数 | 测试阶段或上线后发现的未覆盖场景数 | 个 |
| 高风险问题提前发现数 | 编码前或上线前由 AI/评审提前暴露的问题数 | 个 |

## 2. 使用原则

1. 少量指标先跑起来。
2. 不追求精确到分钟，先保证持续记录。
3. 度量不是追责工具，是改进工具。
4. 每次复盘只选 1 到 3 个最值得改进的问题。
