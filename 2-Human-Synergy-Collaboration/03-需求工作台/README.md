# 03-需求工作台

需求工作台是一条真实需求的执行现场。

它不定义全局规则，不保存可复用资产原件，只保存当前需求从原始材料到复盘沉淀的过程产物。

## 1. 新需求怎么开始

1. 从 `REQ-模板` 复制一份新目录。
2. 目录命名为 `REQ-XXX - 需求名称`。
3. 把全部原始材料放入 `00-原始材料`。
4. 启动 AI 时先让它读取根目录 `README.md` 和 `02-资产层/README.md`。
5. 再读取 `02-资产层/06-Superpowers技能方法/00-技能选择总入口.md`。
6. 第一阶段只做需求澄清和确认冻结台账，不写代码。

推荐启动口令：

```text
启动新需求：REQ-XXX - 需求名称。

需求工作台路径：
<你的本地路径>\Human-Synergy-Collaboration\03-需求工作台\REQ-XXX - 需求名称

请先读取根目录 README.md、02-资产层/README.md、02-资产层/06-Superpowers技能方法/00-技能选择总入口.md、当前需求 00-原始材料 和 STATUS.md。
第一阶段只输出 01-需求澄清/需求澄清.md，确认冻结台账作为其中一个小节。
已确认事项写入冻结台账，后续阶段不得重复提问。
不要写代码，不进入方案设计。
```

## 2. 标准目录

| 目录 | 用途 |
| --- | --- |
| `00-原始材料` | 原始需求、接口文档、截图、会议记录、外部资料 |
| `01-需求澄清` | `需求澄清.md`，含确认冻结台账 |
| `02-影响分析` | `影响分析.md`，含影响模块、影响接口、影响表、风险点 |
| `03-方案设计` | `方案设计.md`，含方案设计、表设计、接口设计、关键取舍 |
| `04-任务拆分` | `任务拆分.md`，含任务包、验收断言、任务级验证目标和 TDD 适用性 |
| `05-开发与联调` | `开发联调记录.md`，含代码理解、实施落点、任务 TDD 记录、外部接口清单、代码清单、联调记录 |
| `06-测试与验收` | `测试验收.md`，含测试结果、验收结论、完成前验证 |
| `07-复盘沉淀` | `复盘沉淀.md`，含复盘结论、可复用经验、资产层更新建议 |

## 3. 阶段推进规则

1. 不跳阶段。
2. 已冻结事项不重复提问。
3. 一阶段一主文档，`STATUS.md` 只做总控。
4. 不默认创建 `v1/v2/v3` 多版本文件，变更记录写入主文档。
5. 确认项按批次汇总，只打断用户确认当前阶段必须确认的问题。
6. 清单用于防漏，阶段文档只记录检查结论，不复制整张清单。
7. 编码前必须在 `05-开发与联调/开发联调记录.md` 中补齐代码理解、实施落点清单，并引用 `04-任务拆分/任务拆分.md` 的任务级验证目标。
8. 涉及三方接口时必须在开发联调记录中补外部接口接入清单；复杂接口才单独建文档。
9. 完成前必须执行验证门禁。
10. 可复用经验在复盘阶段沉淀回资产层。
