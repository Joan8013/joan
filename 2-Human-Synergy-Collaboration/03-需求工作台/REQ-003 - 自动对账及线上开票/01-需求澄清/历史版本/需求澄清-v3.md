# 需求澄清 v3

需求：REQ-003 ETC拓展平台结算服务费开票功能

本版基于原始需求、待确认事项、讨论结果和乐企接口材料重新冻结范围。

## 1. 本期范围

本期只做：

1. 发票开具。
2. 发票查询与结果回写。
3. 发票记录管理页面。
4. 失败重试。
5. 成功下载。

本期不做：

1. 审核流程。
2. 拆票规则。
3. 作废、红冲、换票。
4. 商户手工编辑开票报文。

## 2. 需求目标

1. 前一流程把已确认的待开票数据传入本流程。
2. 本流程对接乐企开票接口和发票查询接口。
3. 商户可查看自己名下的发票记录。
4. 失败记录可重试，成功记录可下载。

## 3. 业务边界

### 3.1 输入边界

本流程只接收前一流程已冻结的数据，不重新决定：

1. 发票类型。
2. 开票金额。
3. 项目明细。
4. 是否拆票。

### 3.2 来源边界

1. 开票金额来源统一追溯到服务费汇总表中的服务费汇总记录。
2. 服务费汇总记录编码必须保留，作为发票来源追踪键。
3. 一条服务费汇总记录可对应多张发票，但拆分结果由前一流程决定。

## 4. 乐企接口口径

1. 本期必须对接乐企开票接口。
2. 本期必须对接乐企发票查询接口。
3. `FPQQLSH` 为开票请求幂等键，20位字母数字组合。
4. 失败重试必须复用原 `FPQQLSH` 和原报文。
5. `LSH` 仅用于异步结果识别，不替代 `FPQQLSH`。

## 5. 开票传参冻结项

本期开票必填且固定口径如下：

1. 购买方名称。
2. 购买方纳税人识别号。
3. 销售方名称。
4. 销售方纳税人识别号。
5. 价税合计。
6. 合计金额。
7. 合计税额。
8. 税率。
9. 发票类型。
10. 开票人。
11. 项目名称。
12. 规格型号。
13. 单位。
14. 数量。
15. 单价。
16. 税收分类编码。

其中：

1. 销售方固定信息由财务统一配置。
2. 项目明细由前一流程完整传入，本流程不编辑。
3. 金额尾差处理由前一流程冻结，本流程不再二次计算。

## 6. 状态与操作

建议保留：

1. 待开票。
2. 开票中。
3. 开票成功。
4. 开票失败。

页面操作：

1. 失败可重试。
2. 成功可下载。
3. 失败原因需展示。

## 8. 结论

1. 本期已从“只开具”升级为“开具 + 查询 + 记录管理”。
2. 现有旧审核/登记链路不纳入本期。
3. 后续方案设计必须围绕前一流程冻结数据、乐企开具、乐企查询和商户记录页展开。
