# 任务拆分 v2

需求：`REQ-003 ETC拓展平台结算服务费开票功能`

本版基于 `方案设计-v3.md` 输出，面向开发落地。

## 1. 数据层

1. 新增 `etcplus_service_fee_invoice` 主表。
2. 新增 `etcplus_service_fee_invoice_retry_log` 日志表。
3. 建立 `fpqqlsh` 唯一索引和查询索引。

## 2. 后端基础对象

1. 新增 `ServiceFeeInvoice` 实体。
2. 新增 `ServiceFeeInvoiceRetryLog` 实体。
3. 新增 `ServiceFeeInvoiceMapper`。
4. 新增 `ServiceFeeInvoiceRetryLogMapper`。

## 3. 乐企接入

1. 新增 `LeqInvoiceClient`。
2. 实现开票接口调用。
3. 实现发票查询接口调用。
4. 统一错误码和返回结果解析。

## 4. 发票业务服务

1. 实现创建并发起开票。
2. 实现 `FPQQLSH` 生成。
3. 实现请求报文固化。
4. 实现同步返回结果回写。
5. 实现失败重试。
6. 实现查询补偿。

## 5. 定时任务/补偿

1. 扫描开票中记录。
2. 调用乐企查询接口。
3. 回写成功、失败、下载地址。

## 6. 商户端接口

1. 发票记录分页查询接口。
2. 失败重试接口。
3. 下载地址查询接口。

## 7. 管理端接口

1. 发票记录查询接口。
2. 发票详情接口。

## 8. 前端改造

1. 改造商户端 `invoiceManage` 页面。
2. 新增正式发票 API 文件。
3. 替换旧占位字段和旧数据源。
4. 增加失败重试确认。
5. 增加 `PDF/OFD/XML` 下载格式选择。
6. 列表页只展示最新一次失败原因，不展示已重试次数和剩余重试次数。

## 9. 测试重点

1. `FPQQLSH` 唯一性。
2. 失败重试复用原报文。
3. `CODE=1000` 查询补偿。
4. 成功下载地址回写。
5. 商户数据隔离。
6. 前端字段命名与主表口径一致。
