## 0. 设计总览（一页纸）

**主链路**：
```text
服务费汇总(recon_bill)
  → 开票申请(apply，按 invoice_limit 拆 1~N 张 detail)
  → 三段审核(运营 → 财务初审 → 财务复审，可退回上一级)
  → 财务复审通过=仅改审核态；由 job-report 定时 Job 首轮建票并调乐企 GP_FPKJ
  → 发票管理(GP_FPCX 查询补偿 / 失败重试 / PDF·OFD·XML 下载)
```

**5 张表**：`apply`(申请头,23列,仅当前态) · `detail`(拆票明细,1~N) · `invoice`(发票执行主表,与detail 1:1) · `retry_log`(开票/重试日志) · `apply_audit_log`(审核历史,只追加)。

**关键决策**：

| 决策 | 结论 | 来源 |
| --- | --- | --- |
| 复审与开票解耦 | 复审 HTTP 仅改审核态，Job 异步首轮开票 | 复审异步开票与防重复设计-v1 |
| 拆票张数 | 读 `invoice_limit`，**禁止硬编码 2 张** | 2026-07-01 修订 |
| 尾差 | **不调平**，各行独立拆税，仅校验 `sum(JSHJ)=可开票金额` | 2026-07-01 修订 |
| 单价 XMDJ | `JSHJ÷1.06` 高精度字符串（总长≤15，≤13位小数） | 联调确认 |
| 乐企备注 BZ | 用汇总周期快照(1–11月`yyyyMM`；12月跨月`yyyyMM-yyyyMM`) | 汇总周期与乐企BZ设计-v1 |
| 幂等兜底 | `fpqqlsh`(LHDF前缀,唯一) + `uk_apply_split_seq` + `uk_detail_id` | §9 |

**外部**：乐企 `GP_FPKJ`(开票)/`GP_FPCX`(查询)，测试环境已联调通过；敏感配置(APPID/AES/证书密码)全部环境变量注入。

## 1. 版本结论

本期方案对齐 **extend_platform 已实现的全链路**：

1. **服务费汇总** → **开票申请（按 `invoice_limit` 拆 1~N 张）** → **运营 / 财务初审 / 财务复审** → **Job 首轮乐企开票** → **发票记录管理（查询 / 重试 / 下载）**。
2. 发票执行主表：`etcplus_recon_bill_invoice`（含 `detail_id`、`split_seq`，与申请明细 1:1）。
3. 重试日志表：`etcplus_recon_bill_invoice_retry_log`。
4. 申请头表：`etcplus_recon_bill_invoice_apply`（**23 列**，仅 `audit_status` / `issue_status` 当前态）。
5. 审核历史：`etcplus_recon_bill_invoice_apply_audit_log`（只追加）。
6. 乐企 `GP_FPKJ` / `GP_FPCX` 测试环境联调已通过；`job-report` 定时轮询 `invoice_status=1` + **复审通过后首轮开票 Job**（每 2 分钟）。
7. 商户端与管理端页面均已实现（见 §10）。
8. 票面规则不变：数量 `"1"`，`unit_price varchar(15)`，`fpqqlsh` 唯一键；**前缀 LHDF**（见 `复审异步开票与防重复设计-v1.md` §5）。

## 2. 本期范围

### 2.1 纳入范围

1. 商户选择服务费汇总单，按 **`invoice_limit`** 填写合并或分开拆票方案（1~N 张，N 为有效数电抬头数）并提交开票申请。
2. 管理端三段审核：运营审核 → 财务初审 → 财务复审（支持退回上一级）。
3. 财务复审通过后，**HTTP 仅更新审核态**；由 `job-report` 定时 Job `issueApprovedApplies` 首轮建票并调用乐企 `GP_FPKJ`（详见 `复审异步开票与防重复设计-v1.md`）。
4. 乐企 `GP_FPCX` 查询补偿 + `job-report` 定时轮询 `invoice_status=1`。
5. 商户端 / 管理端发票列表、详情、下载、失败重试。
6. 审核历史查询（`apply_audit_log` + 管理端「审核记录」）。
7. 保存首次开票与每次重试日志。
8. **汇总周期 → 乐企 BZ**：汇总创建时写死区间快照；申请/发票只拷贝；见 `汇总周期与乐企BZ设计-v1.md` §2、§5。

### 2.2 不纳入范围

1. 红冲、作废、换票。
2. 商户手工编辑乐企报文。
3. 拆票金额**算法**的独立配置中心（拆票在申请 UI 由商户填写，服务端校验金额合计）。
4. 财务侧线下处理流程。

## 4. 数据模型

数据模型以同目录 `发票表设计.md` 为准。

### 4.1 主表

表名：

```text
etcplus_recon_bill_invoice
```

数据库设计原则：

1. 数据库只体现数据结构、字段类型、主键和必要查询索引。
2. 数据库原则上不体现业务逻辑。
3. 发票重复控制、申请单重复控制、**拆票张数上限（`invoice_limit`）**、金额关系、重试资格均由代码负责。
4. `fpqqlsh` 是乐企开票请求流水号，数据库设置唯一键作为外部接口幂等兜底。

关键约束：

| 约束 | 说明 |
| --- | --- |
| 主键 | 仅 `id` 唯一 |
| 唯一键 | `fpqqlsh` 唯一 |
| 无申请单发票序号唯一 | `uk_apply_split_seq (apply_id, split_seq)`、`uk_detail_id (detail_id)` | 代码 + 迁移 SQL 控制，防止同一明细重复开票 |
| `idx_merchant_status` | 支撑商户端按商户和状态查询 |
| `idx_recon_bill_id` | 支撑按服务费汇总记录回溯 |
| `idx_invoice_no` | 支撑按发票号码查询 |

### 4.2 重试日志表

表名：

```text
etcplus_recon_bill_invoice_retry_log
```

日志原则：

1. 首次开票也写日志，`action_type=1`，`retry_no=0`。
2. 每次重新开票写一条新日志，`action_type=2`。
3. 重试不新增发票主表记录。
4. 日志可保存请求快照和响应摘要，但不得保存密钥、证书密码等敏感配置。

## 5. 金额与票面规则

### 5.1 基础口径

最新订正口径：

| 项目 | 口径 |
| --- | --- |
| 金额单位 | 元，保留 2 位小数 |
| 税率 | 固定 `0.06` |
| 数量 | 固定 `1`，0 位小数 |
| 单价 | 动态计算：**XMDJ = JSHJ(元) ÷ 1.06**（乐企精度：总长 ≤ 15、最多 13 位小数） |
| 单价数据库字段 | `varchar(15)`，存 XMDJ 字符串 |
| 项目金额 | `xmje_amount` = `round(JSHJ÷1.06, 2)`，对应乐企 `XMJE` |
| 尾差处理 | **不调平**；各行独立拆税；仅校验 `sum(JSHJ) = 可开票金额` |

### 5.2 单张发票金额计算

每张发票基础计算：

```text
JSHJ = 上游传入价税合计，元，2 位小数
HJJE = round(JSHJ ÷ 1.06, 2)
HJSE = JSHJ - HJJE
XMSL = "1"
XMJE = HJJE
XMDJ = (JSHJ ÷ 1.06) 按乐企精度格式化后的字符串（非 2 位 HJJE 直接转字符串）
```

说明：

1. `JSHJ` 由商户在申请 UI 填写/拆分，单位元，保留 2 位小数。
2. `HJJE/HJSE` 由本模块**按张**独立计算，**不做**整单或最后一张调平。
3. `XMDJ` 与展示用 `HJJE` 分离：XMDJ 从价税合计高精度拆税，满足乐企字段长度规则。
4. `XMSL` 固定为字符串 `"1"`。

### 5.3 拆票张数与金额校验

| 规则 | 说明 |
| --- | --- |
| 张数上限 | `invoice_limit`（商户有效数电抬头数；汇总单创建时快照） |
| 抬头唯一 | 同一业务性质、同一申请内，每条开票信息（抬头）不可重复 |
| 价税合计 | `sum(各行 JSHJ) = 汇总单可开票金额`（分位一致） |
| 分开填写 | 除最后一张外可手工改 JSHJ；最后一张 = 总额 − 其余各行 |

**禁止**：后端将开票条数上限写死为 2（须读 `recon_bill.invoice_limit` / 商户配置）。

### 5.4 乐企备注 BZ（汇总周期）

详见 **`汇总周期与乐企BZ设计-v1.md`**。摘要：

1. **汇总创建**（`createReconBill`）持久化 `period_end_at`、`settlement_period_start`、`settlement_mon_end`。
2. **开票申请**（`applyInvoiceInternal`）`copyToApply`，不重新推导。
3. **发票执行** `remark` → 乐企 `BZ`；`invoice_summary` 固定「服务费」，不使用商户 `invoice_remark`。
4. 1–11 月：`202606`；12 月跨月：`202512-202604`；同一申请下多张票 **BZ 相同**。

### 5.5 乐企字段序列化要求

真实联调已确认：

1. 乐企 DTO 必须通过 `@JsonProperty` 输出大写字段，如 `FPQQLSH`、`JSHJ`、`XSF_NSRSBH`。
2. 金额、数量、单价、税率等 `BigDecimal` 字段按字符串序列化，避免乐企判定必填缺失。
3. 响应不是扁平结构，需要先解析外层 `interface.data.content`，再 Base64 解码业务响应。
4. `XMSL` 输出为字符串 `"1"`。
5. `XMJE` 输出为动态计算值，是项目明细不含税金额；`HJJE = N × XMJE` 的关系由代码保证。
6. `XMDJ` 输出为动态计算值，当前等于 `HJJE` 的字符串形式，同时满足总长度不超过 15 位、最多保留 13 位小数。

## 8. 乐企接口设计

### 8.1 开票接口 `GP_FPKJ`

处理步骤：

1. 主表落待开票记录。
2. 生成 `FPQQLSH`。
3. 组装项目明细和乐企请求报文。
4. 保存 `request_payload` 与 `request_payload_hash`。
5. 写首次开票日志。
6. 调用 exchange。
7. 根据乐企返回更新为成功、失败或开票中。
8. 成功时保存发票号码、发票代码、开票时间、PDF/OFD/XML 地址。

联调结论：

```text
测试环境真实开票成功；
乐企返回 returnCode=0000，业务 CODE=0000；
可返回 PDF/OFD/XML 下载地址。
```

### 8.2 查询接口 `GP_FPCX`

用途：

1. 补偿查询开票中记录。
2. 补齐下载地址。
3. 处理乐企同步延迟导致的短时未查询到。

联调结论：

```text
测试环境链路可访问；
刚开票后查询结果可能受乐企侧同步时点影响。
```

设计要求：

1. 查询未命中不能立即误判失败。
2. 应保留查询补偿状态。
3. 查询任务需限制频率，避免对乐企造成不必要压力。

## 9. 状态与幂等

### 9.1 发票执行状态

| 状态 | 含义 |
| --- | --- |
| `0` | 待开票 |
| `1` | 开票中 |
| `2` | 开票成功 |
| `3` | 开票失败 |

### 9.2 重试规则

1. **商户前端**：仅 `invoice_status=3`（开票失败）展示「重新开票」。
2. **后端** `retryIssue`：允许 `invoice_status` 为 **1（开票中）或 3（失败）**；先 `GP_FPCX` 查询，再决定是否复用 `fpqqlsh` 发起开票。
3. 最大重试 3 次（`retry_count` / `max_retry_count`）。
4. 重试复用原 `FPQQLSH` 与原 `request_payload`。
5. 重试不新增发票主表记录；每次重试新增 retry_log。
6. `invoice_status=2`（成功）禁止重试。

### 9.3 幂等约束

| 场景 | 幂等方式 |
| --- | --- |
| 重复创建同一申请单发票记录 | `uk_apply_split_seq` / `uk_detail_id` + Service 先查后插 |
| 重复提交同一乐企流水 | LHDF 稳定号 + `uk_fpqqlsh` |
| 同一 apply 重复首轮 issue | `issue_start_at` CAS 认领 |
| 同一 invoice 重复 GP_FPKJ | `tryClaimInvoiceForIssue`（`invoice_status=0`） |
| 失败重试 | 复用原主记录、原流水号、原报文 |
| 下载选项查询 | 只读，不改变状态 |

详见 `复审异步开票与防重复设计-v1.md` §6。

## 11. 安全与性能约束

### 11.1 敏感信息

以下信息禁止硬编码，禁止写入文档明文，禁止打印到日志：

1. APPID。
2. AES 密钥。
3. 证书密码。
4. token。
5. 其他乐企侧认证密钥。

运行时来源：

| 配置项 | 来源 |
| --- | --- |
| APPID | 环境变量 `LEQ_APP_ID` 或配置中心 |
| AES 密钥 | 环境变量 `LEQ_CONTENT_PASSWORD` 或配置中心 |
| 证书密码 | 环境变量 `LEQ_CERT_CLIENT_PASSWORD` 或配置中心 |
| 证书文件 | classpath `cert/leq/testISSUE.pfx` |

### 11.2 查询性能

1. 列表查询禁止 `SELECT *`。
2. 列表接口禁止返回 `request_payload`。
3. 列表接口禁止返回 `item_detail_payload`。
4. 查询必须使用 MyBatis 参数绑定，禁止拼接用户输入。
5. 商户端列表必须使用索引字段过滤，避免大字段扫描。

### 11.3 外部接口测试

1. 真实外部接口测试默认跳过。
2. 只有 `LEQ_INTEGRATION_TEST=true` 时允许访问乐企测试环境。
3. 普通编译、普通 CI 不得触发真实开票。
