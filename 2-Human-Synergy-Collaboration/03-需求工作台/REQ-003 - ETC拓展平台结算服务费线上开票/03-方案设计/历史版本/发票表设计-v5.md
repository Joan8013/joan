# 发票表设计 v5

需求：`REQ-003 ETC拓展平台结算服务费开票功能`

本版在 `v4` 基础上做最终收口，补上代码核对结论、MySQL DDL 和日志表定稿。

## 1. 最终结论

本期发票执行域保留两张表：

1. 主表：`etcplus_recon_bill_invoice`
2. 留痕表：`etcplus_recon_bill_invoice_retry_log`

其中：

1. 主表一条记录代表一张单张发票执行明细。
2. 同一申请单下最多 2 条主表记录。
3. 重试不新增主表记录，但每次请求必须新增一条日志记录。

## 2. 与现有代码的对齐结论

结合当前 `ExtendPlatform` 代码核对，现有老链路字段口径如下：

| 现有字段 | 所在对象 | 说明 |
| --- | --- | --- |
| `id` | `TransferBillTotal` / `TransferBillN` | 当前申请或明细主键 |
| `bill_apply_no` | `TransferBillTotal` / `TransferBillN` | 当前申请单号 |
| `bill_state` | `TransferBillTotal` / `TransferBillN` | 当前申请审核/登记状态 |
| `service_real_amt` | `TransferBillTotal` | 当前服务费汇总金额 |
| `biz_nature` | `TransferBillN` | `Integer`，`1=正常交易`、`2=助缴` |
| `invoice_tax_number` | 商户开票/企业信息表 | 商户税号 |
| `invoice_unit_name` | 商户开票信息表 | 发票抬头 |
| `invoice_type` | 商户开票信息表 | 旧系统口径为 `0=专票`、`1=普票` |

本期新表仍使用新领域字段命名，但接入时要明确以下映射：

| 新表字段 | 上游来源 | 备注 |
| --- | --- | --- |
| `apply_id` | 申请单 `id` | 强关联键 |
| `apply_no` | 申请单 `bill_apply_no` | 业务追踪键 |
| `biz_nature` | 上游 `biz_nature` | 直接存整数快照 |
| `buyer_name` | 上游冻结后的购买方名称 | 不在本模块二次查值 |
| `buyer_tax_no` | 上游冻结后的购买方税号 | 不在本模块二次查值 |
| `invoice_type` | 上游映射后的乐企票种代码 | 本表存 `030/032`，不存旧的 `0/1` |

### 3.2 类型定稿说明

1. `biz_nature` 改为 `tinyint`，不再写成文本，因为现有代码就是整数枚举。
2. `invoice_type` 保留 `varchar(8)`，因为本表存的是乐企代码 `030/032`，而不是旧系统 `0/1`。
3. `remark` 定为 `varchar(240)`。
4. `request_payload` 与 `item_detail_payload` 定为 `mediumtext`，不使用 `longtext`。

```sql
CREATE TABLE `etcplus_recon_bill_invoice_retry_log` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `invoice_id` bigint NOT NULL COMMENT '发票主表ID',
  `retry_no` tinyint NOT NULL COMMENT '第几次请求,首次开票记1',
  `action_type` tinyint NOT NULL COMMENT '动作类型:1首次开票,2重试',
  `request_payload_snapshot` mediumtext COMMENT '请求报文快照',
  `response_code` varchar(16) DEFAULT NULL COMMENT '乐企返回码',
  `response_message` varchar(1000) DEFAULT NULL COMMENT '乐企返回信息',
  `trigger_by` varchar(64) DEFAULT NULL COMMENT '触发人',
  `trigger_at` datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '触发时间',
  PRIMARY KEY (`id`),
  KEY `idx_invoice_id` (`invoice_id`),
  KEY `idx_trigger_at` (`trigger_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='服务费汇总开票重试日志表';
```

## 7. 查询性能约束

1. 列表查询禁止 `SELECT *`。
2. 列表接口禁止返回：
   - `request_payload`
   - `item_detail_payload`
3. 这两个字段仅在以下场景读取：
   - 详情查看
   - 失败重试
   - 联调排障

## 8. 最终落地建议

1. 保留新表命名，不回退到旧申请表字段命名。
2. 但代码实现时，要在入参 DTO 和组装逻辑里显式写清楚旧字段到新字段的映射。
3. `biz_nature` 按整数枚举落库最稳，不要再存中文文本。
4. `invoice_type` 在新表中直接存乐企代码，避免后续每次调用接口再做二次转换。
