# 发票表设计 v3

需求：`REQ-003 ETC拓展平台结算服务费开票功能`

本文只聚焦本期服务费发票主表和重试日志表。

## 1. 设计结论

本期建议：

1. 必建主表 `etcplus_service_fee_invoice`
2. 建议建日志表 `etcplus_service_fee_invoice_retry_log`

主表要覆盖：

1. 来源追溯
2. 冻结快照
3. 乐企幂等
4. 开票结果
5. 查询补齐结果
6. 下载地址

## 2. 为什么这次要比 v2 多几个字段

原因不是为了做“大表”，而是新增需求已经明确：

1. 要接乐企查询接口。
2. 要补项目明细固定字段。
3. 要让前端以正式发票字段返回。

所以这次新增字段是业务必需，不是提前过度设计。

## 3. 主表设计

### 3.1 推荐字段

#### 3.1.1 来源关联

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `invoice_id` | bigint | 是 | 主键 |
| `merchant_id` | varchar(64) | 是 | 商户号 |
| `merchant_name` | varchar(128) | 是 | 商户名称快照 |
| `source_record_id` | varchar(64) | 是 | 前一流程待开票记录ID |
| `source_record_type` | varchar(32) | 是 | 来源类型，如 `SERVICE_FEE_APPLY_ITEM` |
| `service_fee_record_code` | varchar(64) | 是 | 服务费汇总记录编码 |

#### 3.1.2 购销方与金额快照

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `buyer_name` | varchar(300) | 是 | 购买方名称 |
| `buyer_tax_no` | varchar(20) | 是 | 购买方税号 |
| `seller_name` | varchar(300) | 是 | 销售方名称 |
| `seller_tax_no` | varchar(20) | 是 | 销售方税号 |
| `jshj_amount` | decimal(18,2) | 是 | 价税合计 |
| `hjje_amount` | decimal(18,2) | 是 | 合计金额 |
| `hjse_amount` | decimal(18,2) | 是 | 合计税额 |
| `tax_rate` | decimal(8,6) | 是 | 税率，固定 `0.060000` |
| `invoice_type` | varchar(8) | 是 | 发票类型，存乐企 `FPLXDM` 值，如 `030/032` |
| `drawer_name` | varchar(64) | 是 | 开票人 |

#### 3.1.3 项目明细固定字段

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_name` | varchar(128) | 是 | 项目名称 |
| `specification_model` | varchar(128) | 否 | 规格型号 |
| `unit_name` | varchar(32) | 否 | 单位 |
| `quantity` | decimal(18,6) | 是 | 数量 |
| `unit_price` | decimal(18,15) | 是 | 单价 |
| `tax_class_code` | varchar(32) | 是 | 税收分类编码 |
| `item_detail_payload` | longtext | 是 | 明细原始快照 |

#### 3.1.4 乐企幂等与请求

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `fpqqlsh` | varchar(20) | 是 | 开票请求流水号 |
| `lsh` | varchar(36) | 否 | 异步流水号 |
| `request_payload` | longtext | 是 | 实际请求报文 |
| `request_payload_hash` | varchar(64) | 是 | 报文摘要 |

#### 3.1.5 结果与查询

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `invoice_status` | tinyint | 是 | 0待开票、1开票中、2开票成功、3开票失败 |
| `query_status` | tinyint | 否 | 查询补偿状态 |
| `retry_count` | int | 是 | 已重试次数 |
| `max_retry_count` | int | 是 | 最大重试次数，默认3 |
| `last_request_at` | datetime | 否 | 最近请求时间 |
| `last_response_at` | datetime | 否 | 最近响应时间 |
| `return_code` | varchar(16) | 否 | 乐企返回码 |
| `return_message` | varchar(1000) | 否 | 乐企返回消息 |
| `fail_reason` | varchar(1000) | 否 | 对前端展示的失败原因 |
| `invoice_code` | varchar(32) | 否 | 发票代码 |
| `invoice_no` | varchar(32) | 否 | 发票号码 |
| `invoice_date` | datetime | 否 | 开票时间 |
| `pdf_url` | varchar(1000) | 否 | PDF下载地址 |
| `ofd_url` | varchar(1000) | 否 | OFD下载地址 |
| `xml_url` | varchar(1000) | 否 | XML下载地址 |

#### 3.1.6 审计字段

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `create_by` | varchar(64) | 否 | 创建人 |
| `create_at` | datetime | 是 | 创建时间 |
| `update_by` | varchar(64) | 否 | 更新人 |
| `update_at` | datetime | 是 | 更新时间 |

### 3.2 明确不加的字段

1. 审核字段
2. 逻辑删除字段
3. 红冲作废字段
4. 拆票规则字段
5. 购买方开户地址电话等未冻结字段

## 4. 推荐约束

1. 主键：`invoice_id`
2. 唯一键：`uk_fpqqlsh (fpqqlsh)`
3. 索引：`idx_merchant_status (merchant_id, invoice_status)`
4. 索引：`idx_service_fee_record_code (service_fee_record_code)`
5. 索引：`idx_source_record (source_record_id, source_record_type)`
6. 索引：`idx_invoice_no (invoice_no)`

## 6. 日志表设计

推荐继续保留 `etcplus_service_fee_invoice_retry_log`。

原因：

1. 乐企失败重试必须复用原报文。
2. 联调时需要核对每次请求内容。
3. 财务/业务排障时需要看到每次请求结果。

## 7. 结论

1. `etcplus_service_fee_invoice` 比 v2 多出的字段，主要是项目明细固定字段和查询补偿字段。
2. 当前版本仍然是收敛设计，不算虚胖。
3. 如果后续范围不再扩大，这个字段规模已经接近本需求的最优平衡点。
