# REQ-模板

这是单条需求的标准目录模板。

复制本目录后，将目录名改成真实需求编号和名称，例如：

```text
REQ-2026-001-示例需求
```

## 1. 标准结构

| 目录/文件 | 作用 |
| --- | --- |
| `README.md` | 本需求导航和阅读顺序 |
| `STATUS.md` | 当前阶段、阻塞项、待确认项、下一步 |
| `00-原始材料` | 原始输入和证据 |
| `01-需求澄清/需求澄清.md` | 范围、非范围、确认冻结台账、待确认项 |
| `02-影响分析/影响分析.md` | 模块、接口、数据、风险影响 |
| `03-方案设计/方案设计.md` | 技术方案、业务方案、关键取舍 |
| `04-任务拆分/任务拆分.md` | 开发任务、联调任务、验收任务、任务级验证目标和 TDD 适用性 |
| `05-开发与联调/开发联调记录.md` | 代码理解、实施落点、任务 TDD 记录、外部接口、代码清单、联调记录 |
| `06-测试与验收/测试验收.md` | 测试结果、完成前验证、验收结论 |
| `07-复盘沉淀/复盘沉淀.md` | 复盘、经验、资产改进建议 |

## 2. 维护原则

1. 原始材料不随意改写。
2. `STATUS.md` 保持短而准。
3. 每个阶段默认只维护一个主文档。
4. 专项复杂问题可以单独建专题文档。
5. 不默认创建 `v1/v2/v3` 多版本文档，变更记录写入主文档。
6. 需求结束后必须补复盘和度量记录。
