# 任务拆分 v1

需求：REQ-DEMO-001 助缴成功率和成本统计报表

本文用于最小试跑，目标是展示一个 B 类报表需求如何拆成可执行任务包。

## 1. 任务包拆分

| 任务包 | 内容 | 验收点 |
| --- | --- | --- |
| T-001 表结构与初始化 | 新增 `ep_ap_success_cost_report`，补充菜单、权限、定时任务脚本 | 脚本可重复执行，菜单可见，任务配置存在 |
| T-002 报表聚合任务 | 实现每日重建、条件重建、按上传日期和订单更新时间刷新 | 指定日期重建后结果表数据正确 |
| T-003 后端查询与导出 | 提供列表、合计、导出接口 | 明细分页正确，合计行加权成功率正确，导出金额单位正确 |
| T-004 前端页面 | 查询条件、列表、合计行、导出、金额和百分比展示 | 查询/重置/分页/导出可用，空分母显示 `-` |
| T-005 测试造数与验证 | 构造多商户、多状态、多短信、多车牌测试数据 | 可验证数量、金额、收益、成功率 |

## 2. 最小开发顺序

1. 先落表结构和初始化脚本。
2. 再实现报表聚合任务，确认结果表口径。
3. 再实现后端查询和合计。
4. 最后实现前端展示和导出。
5. 用测试造数脚本跑一轮端到端验证。

## 3. AI 可辅助点

| 阶段 | AI 适合做什么 | 人必须确认什么 |
| --- | --- | --- |
| 需求澄清 | 从 Word/Excel 抽字段、找冲突、整理问题清单 | 成功率、金额、收益、状态口径 |
| 影响分析 | 搜索代码、定位表、接口、Mapper、页面 | 是否沿用现有模式，是否影响资金链路 |
| 方案设计 | 生成数据流、接口草案、SQL 聚合草案 | 统计口径和边界 |
| 开发联调 | 辅助生成 Mapper、页面、测试数据脚本 | 关键 SQL、金额单位、上线风险 |
| 测试验收 | 生成测试点、边界场景、验收清单 | 验收结果和业务接受度 |

## 4. 不应交给 AI 自动决定的事项

1. 成功率到底采用车牌口径还是短信口径。
2. 报表是否作为财务对账或结算依据。
3. 已补缴状态是否只看 `status = 2`，还是必须同时看 `pay_status = 2`。
4. 默认日期到底是当天还是昨天。
5. 导出是否属于本期范围。
