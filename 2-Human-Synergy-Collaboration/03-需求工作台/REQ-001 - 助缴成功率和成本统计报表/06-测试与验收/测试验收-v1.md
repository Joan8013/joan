# 测试与验收 v1

需求：REQ-DEMO-001 助缴成功率和成本统计报表

本文用于最小试跑，重点不是穷尽测试用例，而是展示 B 类报表需求必须覆盖的验收面。

## 1. 核心验收标准

| 编号 | 验收点 | 通过标准 |
| --- | --- | --- |
| AC-001 | 页面入口 | 运营后台可进入“助缴成功率及成本统计报表” |
| AC-002 | 日期查询 | 按上传日期范围查询，结果按商户和日期展示 |
| AC-003 | 明细统计 | 上传、接收、短信、车牌、补缴、金额、收益字段与结果表一致 |
| AC-004 | 合计统计 | 数量和金额求和，成功率按 `合计已补缴流水数 / 合计发送短信数量` 计算 |
| AC-005 | 金额展示 | 数据库存分，页面和导出按元展示，保留 2 位小数 |
| AC-006 | 成功率展示 | 数据库存小数，页面展示百分比；分母为 0 时展示 `-` |
| AC-007 | 导出 | 导出字段、金额、成功率与页面口径一致 |

## 2. 最小测试场景

| 场景 | 目标 |
| --- | --- |
| 单商户单日有上传、有短信、有补缴 | 验证正常主链路 |
| 单商户单日有上传但无平台接收 | 验证 0 值和空结果处理 |
| 同一车牌多笔已补缴订单 | 验证车牌去重和流水数差异 |
| 有短信但无补缴 | 验证成功率为 0 |
| 无短信 | 验证成功率展示 `-` |
| 多商户同日 | 验证商户维度分组和合计 |
| 日期区间多日 | 验证按日拆行和合计 |

## 3. 造数脚本期望

`test-scripts/SeedAssistPayReportTestData.java` 中给出的典型期望包括：

| 商户 | 关键期望 |
| --- | --- |
| APTEST-M1 | 平台接收 3，短信 2，已补缴车牌 1，已补缴流水 2，成功率 1.0000 或按现有脚本期望核对 |
| APTEST-M2 | 有上传但无接收，金额和收益为 0 |
| APTEST-M3 | 平台接收 2，短信 1，已补缴车牌 2，已补缴流水 2 |

注意：脚本打印的历史期望需要和当前成功率口径再次核对，不能机械照抄。

## 4. 验收结论模板

| 项目 | 结论 |
| --- | --- |
| 业务口径 | 以现有报表实现口径验收 |
| 资金影响 | 不影响交易、清分、结算、划账 |
| 数据验证 | 需至少完成一组可解释样例数据核对 |
| 上线前置 | 菜单、权限、任务、脚本、导出均需检查 |
