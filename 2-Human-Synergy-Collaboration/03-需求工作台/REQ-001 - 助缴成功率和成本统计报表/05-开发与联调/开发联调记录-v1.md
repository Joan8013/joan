# 开发与联调记录 v1

需求：REQ-DEMO-001 助缴成功率和成本统计报表

本文用于最小试跑，记录已完成实现的关键链路和联调入口。

| 环节 | 代码位置 | 说明 |

## 2. 联调最小路径

1. 执行数据库初始化脚本 `sql/testhtjf/assist_pay_success_cost_report.sql`。
2. 准备助缴上传、订单、短信、交易流水测试数据。
3. 执行任务 `jobEpApSuccessCostReportTask.rebuildByCondition(...)` 或每日任务。
4. 查询 `ep_ap_success_cost_report`，确认结果表数据。
5. 打开运营后台页面，按上传日期查询。
6. 校验页面明细、合计、金额、成功率和导出。

## 3. 已知实现细节

| 事项 | 当前实现 |
| --- | --- |
| 页面默认日期 | 默认昨天 |
| 分母为 0 的成功率展示 | 前端展示 `-` |
| 合计行位置 | 后端把合计行放在列表第一行 |
| 金额单位 | 数据库存分，页面和导出展示元 |
| 成功率存储 | 数据库存小数，如 `0.5000`，页面展示为 `50.00%` |
| 报表数据来源 | 页面查询结果表，不实时扫原始业务表 |

## 4. 联调风险记录

| 风险 | 现象 | 建议 |
| --- | --- | --- |
| 初始化脚本和代码字段不同步 | 查询报错或字段缺失 | 脚本随代码版本一起评审 |
| 报表任务未跑 | 页面无数据 | 先查结果表，再查原始表 |
| 成功率口径被误改 | 页面和运营预期不一致 | 以现有实现口径为基准，变更需另提 |
| 默认日期理解偏差 | 用户以为查当天但页面默认昨天 | 在需求或操作说明中明确“默认昨日” |
