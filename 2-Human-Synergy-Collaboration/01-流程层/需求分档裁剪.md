# 需求分档裁剪

目的：按风险等级（A/B/C，定义见 `00-治理层/AI适用边界与风险分级.md`）匹配不同深度的流程，
**让小需求别走全套、让高风险需求一步不少**。分档是"匹配风险"，不是"降低质量"。

## 0. 铁律（任何档位都不裁）

无论 A/B/C，以下永不裁剪：

1. **安全红线**（不硬编码密钥、不拼 SQL、不打敏感日志、不绕权限、外部真实接口默认关）。
2. **资金/关键口径冻结（IMP-001）**：凡涉及金额/尾差/张数/幂等/清分/结算/退款/税额，**必须在澄清阶段冻结具体值**，不因档位低而省。
3. **完成前验证**：不验证不宣称完成。
4. **A 类不得降档、不得跳步。**

## 1. 定档时机与责任

- 在 **需求澄清阶段初判风险等级**（检查清单第 1 节"风险等级已初判"）。
- 定档由**需求 Owner/技术负责人**确认，写入 `STATUS.md`。
- 存疑就上靠（就高不就低）；涉及资金一律 A。

## 2. 分档流程矩阵

| 阶段 / 关口 | A 类（资金/状态/幂等/对账/跨系统） | B 类（核心流程/多模块） | C 类（文案/展示/低风险配置/脚本） |
| --- | --- | --- | --- |
| 00 原始材料 | 必做 | 必做 | 必做 |
| 01 需求澄清 | 完整 + **澄清确认单 + 资金口径必答区** | 澄清要点 + 资金口径涉及则必冻结 | 一句话确认范围/非范围 |
| 02 影响分析 | 完整（模块/接口/数据/风险） | 简版（影响模块 + 风险要点） | 可并入澄清，标注影响点即可 |
| 03 方案设计 | 完整（决策 DEC + DDL + 接口契约） | 简版（关键设计要点 + 取舍） | 通常免；如有则一句话 |
| 04 任务拆分 | 完整（任务 + 验收断言 + TDD 适用性 + 首个失败断言） | 简版（任务 + 验收断言） | 可并入，列改动点 + 验收点 |
| **关口一 澄清确认单** | **强制**（阻塞项 + 资金口径必答全冻结） | 资金口径涉及则冻结；其余轻量 | 口头/一句话确认即可 |
| 05 开发与联调 | 编码前理解确认 + 任务 TDD 红绿(留红灯证据) + 编码约定 | 编码前要点 + 关键路径 TDD + 编码约定 | 遵编码约定 + 自测 |
| **关口二 编码前理解确认** | **强制** | 关键/复杂任务做 | 免 |
| 06 测试与验收 | **测试可信度报告（含变异）+ 验收清单五步** | 测试 + AC↔测试映射 + 关键验收 | 基础自测 + 抽验 |
| **关口三 测试可信度报告** | **强制（AC映射+红灯+变异+假测试自检）** | AC 映射 + 红灯；变异可选 | 基础测试通过即可 |
| **关口四 验收清单** | **五步全 + Go/No-Go** | 业务验收 + 测试可信度 + Go/No-Go | 抽验 + Go |
| 07 复盘沉淀 | 必做 + 回填度量 | 简版复盘 | 可选（有可复用经验才写） |

## 3. 一句话选择

```text
涉及钱/状态/幂等/对账/跨系统  → A：全套，一步不少
核心业务流程/多模块           → B：留澄清+方案要点+关键TDD+验收
文案/展示/低风险配置/脚本      → C：轻量，守安全红线即可
拿不准                        → 就高不就低
```

## 4. 与其他规则的关系

- 定档写入 `STATUS.md`，各阶段准出按本矩阵要求（见 `阶段准入准出规则.md`）。
- 四关必停（`README §0 执行铁律`）：A 全停；B 停关键关口；C 至少在"可否发布"停一次。
- 单一现行文档规则（禁 -v2/-v3）对所有档位生效。
